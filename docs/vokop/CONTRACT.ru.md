# Контракт Vokop ↔ 3x-ui, версия 1

Нормативные реализации клиента:

- `vokop/files/usr/lib/subscription/vkturn.uc`;
- `vokop/files/usr/lib/management/client.uc`;
- `tools/vokop-fetch/`;
- `vokop/files/usr/lib/providers/vkturn/runtime.uc`.

Контракт принадлежит Vokop. Не называть его существующим стандартом `vkturn://` или готовым API upstream 3x-ui.

## 1. Два независимых канала

1. **Подписка:** пользователь добавляет HTTPS URL в обычный интерфейс подписок Vokop. Панель возвращает JSON `vokop.subscription.v1`; локальный клиент строит VLESS outbound на loopback и отдельный VK TURN процесс. Авторизация URL подписки не даёт права управлять роутером.
2. **Управление:** пользователь отдельно включает локальное разрешение и устанавливает уникальный токен устройства. Роутер сам опрашивает панель по HTTPS. Входящий порт управления на WAN не открывается. Панель не получает SSH/root-доступ.

Не смешивать токен устройства, административную сессию 3x-ui, секрет URL подписки и VLESS UUID. Это разные назначения и области отзыва.

## 2. Доставка подписки

Путь подписки определяется панелью; клиент принимает её полный URL из локальной настройки. Рекомендуемый новый маршрут панели — `/sub/vokop/{opaque_subscription_token}`, но это рекомендация для панели, не жёстко заданный путь роутера.

- Только HTTPS с доверенным сертификатом, без редиректов, userinfo или URL fragment. Сертификат нельзя игнорировать.
- Ответ `200`, `Content-Type: application/json`; тело JSON UTF-8, не Base64.
- Максимум тела Vokop-конверта — 262144 байта, максимум 16 профилей на источник.
- Все ключи схемы обязательны; лишние и дублирующиеся JSON-ключи запрещены.
- `schema`: ровно `vokop.subscription.v1`.
- `revision`: целое от 1 до 9007199254740991. Монотонно увеличивается в пределах одной подписки при изменении любых полей. Одинаковая ревизия с изменившимися данными отклоняется. Старая ревизия отклоняется. Перевод уже управляемого источника в обычный неуправляемый формат тоже отклоняется.
- `issued_at`, `expires_at`: целые UNIX-секунды UTC, не миллисекунды и не ISO-строки. `issued_at` не более чем на 300 секунд в будущем, `expires_at > issued_at`, срок конверта не более 2678400 секунд (31 день). Уже истёкший конверт не принимается.
- Профили имеют уникальный `id` (1–64 ASCII символа; буквы, цифры, `.`, `_`, `-`, первый символ буква/цифра), `name` до 100 символов без управляющих символов.
- `vless` содержит **только** `uuid`. В версии 1 нет произвольных Xray/sing-box объектов, REALITY, xhttp, TLS-параметров или команд из панели.
- `turn.peer_host`: DNS-имя с точками или IPv4; версия 1 не принимает IPv6 literals. Не передавать `host:port` одним полем. Локальные/loopback/мультикаст назначения не использовать. DNS-имя не является доказательством публичного назначения: панель должна проверять свои настроенные серверы отдельно.
- `turn.peer_port`: целое 1–65535. Это порт VK TURN **сервера**, не Xray inbound и не порт LuCI.
- `turn.vk_call_url`: разрешённая HTTPS-ссылка звонка VK; нормативный пример — `https://vk.com/call/join/DEMO_TOKEN`. Без произвольного домена, query/fragment и дополнительных аргументов процесса.
- `turn.streams`: целое 1–16. Начинать с малого значения для слабых роутеров.

Схема JSON проверяет форму; относительное время, монотонность ревизий, уникальность ID и сетевые ограничения проверяются дополнительно кодом. Примеры не являются действующими подписками.

### Серверная сторона транспорта

Один профиль связывает VLESS UUID с доступным VK TURN сервером, перенаправляющим TCP к разрешённому локальному VLESS inbound Xray. Клиент sing-box обращается к `127.0.0.1`, а соединение до VPS выполняет transport sidecar. Не публиковать Xray inbound без необходимости; существующие REALITY/xhttp inbound пользователей не переделывать под этот профиль.

Локальные порты, пути файлов, socket mark и команды запуска выбирает роутер. Панель их не задаёт. Не обещать аутентификацию сервера только на основании транспортного DTLS: upstream транспорт и внутренний VLESS требуют отдельной оценки доверия.

## 3. Управление устройством

Локальная UCI-конфигурация: `/etc/config/vokop_management`, секция `settings`:

- `enabled`: по умолчанию `0`;
- `panel_url`: HTTPS base URL без query/fragment/userinfo; может включать префикс пути;
- `device_id`: использовать совместимое с UI подмножество `[A-Za-z0-9][A-Za-z0-9_-]{0,63}`;
- `token_file`: только `/etc/vokop/management.token`, обычный файл с правами `0600`;
- `poll_seconds`: 30–3600, по умолчанию 60.

Панель должна иметь действие администратора «Создать устройство Vokop»: создать случайный device ID и отдельный криптографически стойкий bearer token с минимум 128 бит энтропии. Хранить проверочный хеш токена, показать исходный токен один раз в защищённом интерфейсе. Это функция панели, не существующий enrollment endpoint роутера. Не присылать токены в логи, Git или телеметрию. Не использовать общий админский API-ключ панели.

Токен устанавливается локально владельцем устройства безопасным способом, а управление включается отдельно. Не включать управление только из-за наличия подписки. Ротация и отзыв device token — отдельные действия панели; отзыв токена управления сам по себе не отзывает VLESS.

### Получение команд

`GET {panel_url}/api/vokop/v1/devices/{device_id}/commands?after={last_id}`

Заголовок `Authorization: Bearer <device_token>`; HTTPS, без редиректов. Успех — `200` с JSON:

```json
{"schema":"vokop.commands.v1","commands":[{"id":1,"type":"refresh_subscriptions","expires_at":1793044800}]}
```

Пустая очередь: `{"schema":"vokop.commands.v1","commands":[]}`. Не отвечать `204` на GET: требуется валидный конверт.

- Максимум 16 команд, тело не более 65536 байт.
- Командные ID — положительные целые до 9007199254740991, строго возрастают в ответе и монотонны для устройства. Не переиспользовать ID.
- Возвращать только команды после `after`. Клиент дополнительно пропускает уже обработанные ID.
- `expires_at` — UNIX-секунды, не более чем на 86400 секунд вперёд относительно времени клиента. Истёкшая команда получает `expired` без исполнения.
- Лишних полей нет. Никаких `args`, `script`, путей, URL загрузки, паролей, UCI-фрагментов или команд shell.

Разрешённые типы:

| Тип | Действие | Ограничение |
|---|---|---|
| `refresh_subscriptions` | Запросить обновление уже локально настроенных подписок | Не добавляет источник и не меняет его URL |
| `restart_vkturn` | Перезапустить локальные VK TURN процессы | Не снимает локальный/удалённый sticky disable |
| `disable_vkturn` | Установить sticky disable и остановить VK TURN | Восстановление только локальным действием владельца |

Неизвестный тип получает `rejected`, не выполняется. Нет команды запуска произвольной программы, смены Wi-Fi/LAN/DHCP, прошивки, перезагрузки ОС или отключения других VPN.

### Подтверждение

`POST {panel_url}/api/vokop/v1/devices/{device_id}/ack`

Тот же bearer token; `Content-Type: application/json`:

```json
{"schema":"vokop.ack.v1","results":[{"id":1,"status":"applied"}]}
```

`status`: `applied`, `failed`, `expired`, `rejected`. Сервер принимает повтор одного и того же результата идемпотентно; принимает только команды этого устройства и не допускает смену окончательного результата без расследования. Возвращает `204` или `200` после надёжного сохранения. Не возвращать `202`: клиент считает его ошибкой.

Клиент сохраняет результаты на устройстве. Неподтверждённый batch повторяется перед следующей загрузкой команд. Потеря питания между исполнением действия и записью состояния может привести к повторному действию. Это **не exactly-once**: три разрешённых действия должны оставаться безопасными при повторе. ACK `applied` означает успешный возврат локальной операции, а не доказанную доступность интернета/успешность подписки.

### Ошибки и наблюдаемость

`401` — неверный/отозванный токен; `403` — доступ запрещён; `429` — ограничение запросов; `5xx` — временная ошибка. Клиент сейчас не раскрывает HTTP-код в локальном статусе и повторяет по своему интервалу, без обработки `Retry-After`; панель не должна полагаться на адаптивный backoff.

Локальные статусы управления: `disabled`, `invalid_local_config`, `ack_pending`, `panel_unavailable`, `invalid_response`, `state_write_failed`, `ready`. Это локальная диагностика, не endpoint телеметрии. Панель может показывать время последнего опроса/ACK, но **не должна** представлять его как состояние туннеля. Версия 1 не отправляет аппаратный fingerprint или произвольный системный отчёт.

## 4. Истечение и отзыв доступа

Проверка оплаты/entitlement должна выполняться **на сервере 3x-ui/Xray**, а не только клиентом. По окончании срока блокировать соответствующий VLESS UUID независимо от того, подключён ли роутер к панели.

- Срок конверта не длиннее фактического оплаченного доступа. Для тарифов 3/6/12 месяцев выдавать возобновляемые конверты максимум на 31 день, а не годовой JSON.
- `401/403` на обновление подписки не является командой немедленно удалить ещё действующий кеш. Пустой `profiles` запрещён. Поэтому отзыв только URL подписки недостаточен.
- Для срочной остановки использовать серверное выключение VLESS UUID. Дополнительно можно поставить `disable_vkturn`, понимая, что команда придёт только при связи с панелью и останется sticky.
- Продление после sticky disable требует локального возобновления; удалённый `restart_vkturn` его не отменяет. Не выдавать оплату за обещание автоматического снятия локальной блокировки.
- Истечение конверта останавливает связанные sidecar-процессы при работающем watchdog и корректных часах; сетевые разрывы, перезагрузка и работа часов проверяются на стенде.

## 5. Правила безопасности панели

Отдельное разрешение для администратора на управление устройствами, CSRF-защита браузерных действий, проверка принадлежности устройства пользователю/подписке, ограничение частоты, журнал действий без секретов, отсутствие секретов в URL управления. GET/ACK доступен только токену конкретного устройства. Админские endpoints не должны принимать device token.

Не применять пользовательский JSON как конфиг Xray и не выполнять поля подписки через shell. Изменения серверных inbound должны идти через существующие валидированные сервисы панели. Не менять остальные подписки, Telegram-бота, оплаты и протоколы ради этой интеграции.
