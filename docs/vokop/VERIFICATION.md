# Vokop: проверка рабочего снимка

Дата: 25 октября 2026. Это промежуточный исходный снимок, не проверенный на роутере релиз.

## База

- Forkop: `ushan0v/forkop`, commit `dd483297be0ac4e52bb8f482e2640238b75af532`.
- VK TURN: `cacggghp/vk-turn-proxy`, commit `e8a96967dc66f3dbd631596ea6a8b9fe03f9be69`.
- Основной пакет переименован в Vokop; исходные лицензии сохранены.

## Выполнено

Проверки выполнялись в облачном рабочем каталоге без подключения к роутеру, VK или панели, без пользовательских токенов.

- 51 новый изолированный Python/ucode тест: строгий формат подписки, повторные/пониженные ревизии, дублирующиеся JSON-ключи, внедрение команд, диапазоны, procd-планы, локальное разрешение, выключатель, истечение срока, состояния watchdog. UCI, ubus, curl и внешние действия подменены заглушками.
- Контракт управления: разрешённые команды, поля, последовательность ID, ограничения срока и HTTPS.
- Очередь управления: повтор ACK после ошибки без повторного выполнения; изоляция очереди при смене панели/устройства; проверка срока каждой команды после медленной предыдущей.
- LuCI управления: валидация, явные локальные кнопки запуска/отзыва, порядок сохранения и выполнения, повторные клики, ошибки остановки, отсутствие доступа к токену через ACL.
- `vokop-fetch`: Go unit tests, race detector и `go vet`; локальный тестовый TLS-сервер, запрет redirect, размер ответа, приватные файлы, допустимые заголовки, прямой DNS-bootstrap.
- Синтаксическая компиляция 61 ucode-модуля; проверки синтаксиса изменённых shell/JavaScript-файлов.
- Сценарий cross-build проверен только с поддельным компилятором; проверены выбор архитектур и SHA256SUMS. Это не сборка транспортного кода.
- Патч транспортного кода применим к зафиксированному upstream; gofmt разбирает его синтаксис.

## Не выполнено / ожидается

- Запуск регрессионных тестов и сборки сторонних исходников Forkop/VK TURN: требуется разрешение пользователя.
- Компиляция VK TURN и полная матрица архитектур.
- Полные тесты и сборка frontend на зависимости из lock-файла.
- OpenWrt SDK-сборка всех целевых `.ipk`/`.apk`, установка, реальные procd/nftables/DNS/Wi-Fi сценарии, реальное VK-соединение.
- Сквозная проверка с настоящим форком 3x-ui: панель ещё должна быть адаптирована по контракту.
- Публикация в GitHub: коннектор вернул отказ доступа, требуется исправление доступа владельцем.

## Важные границы

- Нельзя утверждать «работает на любом OpenWrt с AmneziaWG». База и зависимости требуют отдельной проверки; Go cross-build не является подтверждением работы прошивки.
- «Процесс запущен» и «порт открыт» не считаются исправным туннелем. Watchdog использует настоящий HTTPS-запрос через локальный SOCKS-пробник; в проведённых тестах сеть подменена.
- Предварительная проверка конфигурации и восстановление пары config/plan при ошибке записи не являются доказанным полным откатом сетевых изменений. Сквозная проверка туннеля происходит после запуска.
- Сервер должен самостоятельно прекращать доступ при истечении/отзыве подписки. Локальный watchdog не заменяет серверную авторизацию.
- Автоматический installer и прежний release workflow отключены. `build.sh` создаёт только часть пакетов и требует явного `VOKOP_ALLOW_PARTIAL_PACKAGES=1`; полную сборку следует делать через целевой SDK, включая `vokop-fetch` и `vokop-vk-turn`.
- Все унаследованные CI workflows сохранены как `.disabled` в `docs/upstream/workflows`, чтобы публикация исходников не запускала сторонний код без разрешения.

## Команды для следующего этапа (после разрешения)

1. `cd transport/vk-turn-proxy && go test ./client && go vet ./client`
2. `bash tools/build-vokop-binaries.sh` — только компиляция, не запуск бинарников.
3. `cd fe-app-vokop && yarn install --frozen-lockfile --ignore-scripts && yarn test --run && yarn build`
4. Проверить и запустить подходящие `tests/*.sh` с host ucode и временными заглушками; не запускать installer или сервисы на облачном хосте.
5. По инструкции `transport/README.md` собрать пакеты в SDK конкретной прошивки; затем выполнить локальный стендовый чеклист `docs/vokop/TEST_AND_DEPLOY.ru.md`.
